Introducción a HTML, Convenciones y Clean Code

Guía fundamental sobre la naturaleza de HTML, principios de desarrollo limpio, estándares de formateo y comparativa de prácticas recomendadas frente a errores habituales.

1. Contexto y Naturaleza de HTML

HTML significa HyperText Markup Language (Lenguaje de Marcado de Hipertexto).

  • No es un lenguaje de programación: No posee estructuras de control (bucles, condicionales) ni ejecuta lógica algorítmica. Es un lenguaje de marcado basado en etiquetas que define la estructura y el significado del contenido web.
  • Hipertexto: Hace referencia a la capacidad de interconectar documentos mediante enlaces o hipervínculos (la base de la World Wide Web ideada por Tim Berners-Lee en 1989).
  • Estándar Vivo (HTML Living Standard): Mantenido por el WHATWG y el W3C, garantiza la compatibilidad entre navegadores sin requerir versiones breaking como las antiguas transiciones de HTML4 a XHTML.

2. Convenciones de Nomenclatura y Archivos

Seguir unas reglas claras al nombrar archivos evita errores de enlace en servidores web (especialmente en Linux) y facilita que los motores de búsqueda entiendan tu web:

  • Usa solo minúsculas (Case sensitivity): Los servidores Linux diferencian entre mayúsculas y minúsculas. Usa seccion-contacto.html en lugar de SeccionContacto.HTML para evitar enlaces rotos.
  • Separa las palabras con guiones medios (kebab-case): Utiliza guiones medios como en buenas-practicas.html. Evita los espacios en blanco (buenas practicas.html) y los guiones bajos (buenas_practicas.html), ya que los buscadores no los leen de la misma forma.
  • Evita caracteres especiales y tildes: Los servidores no siempre gestionan bien las eñes o las tildes. Escribe introduccion.html en lugar de introducción-español.html.
  • Usa index.html para la página principal: El servidor busca automáticamente index.html como punto de entrada por defecto al cargar tu dominio, por lo que no debes llamarla Inicio.html ni home.html.

3. Arquitectura de Carpetas (Scaffolding)

En la industria profesional, el orden de los archivos es el primer paso del Clean Code. Nunca se guardan decenas de archivos sueltos en el directorio principal, ya que dificulta la escalabilidad y el mantenimiento del proyecto.

  • La raíz (Root): El directorio principal del proyecto debe contener obligatoriamente el archivo index.html. Cuando subas tu web a un servidor real, este buscará automáticamente ese archivo exacto para arrancar la página principal.
  • Carpetas organizativas: El resto de documentos HTML secundarios deben agruparse en subcarpetas lógicas, comúnmente llamadas /pages o /views.
  • Recursos estáticos (Assets): Las imágenes, iconos y, más adelante, los archivos de diseño (CSS) y lógica (JS), se guardan separados en una carpeta genérica llamada /assets.

Demostración visual de un árbol de carpetas

/tu-proyecto-html
├── index.html                <!-- Único HTML en la raíz (Portada) -->
├── /pages                    <!-- Carpeta para el resto de páginas -->
│   ├── 1-login.html
│   ├── 2-signup.html
│   └── 3-terms.html
├── /assets                   <!-- Carpeta para recursos estáticos -->
│   ├── /img                  <!-- Imágenes, iconos y logotipos -->
│   ├── /css                  <!-- Hojas de estilo -->
│   └── /js                   <!-- Archivos de JavaScript -->

4. Tabulaciones, Indentación y Estructura Visual

El código limpio facilita la lectura y el mantenimiento en entornos colaborativos:

  • Indentación estándar: Se recomienda usar 2 espacios (o 4 espacios según el equipo) por cada nivel de anidamiento. Evita mezclar tabulaciones y espacios.
  • Minúsculas obligatorias: Escribe todas las etiquetas y atributos en minúsculas (ej. <div class="contenedor"> en lugar de <DIV CLASS="contenedor">).
  • Comillas en atributos: Encierra siempre los valores de los atributos en comillas dobles "" (ej. class="boton" en lugar de class=boton).

5. Separación de responsabilidades Semántica y estilos

  • Separación de Responsabilidades: HTML define estructura y contenido; CSS se encarga del diseño visual; JavaScript gestiona la interactividad. No uses estilos en línea (style="") ni eventos JS incrustados.
  • Principio de Accesibilidad (A11y): Incluye siempre el atributo alt="" descriptivo en imágenes y utiliza etiquetas como <main>, <nav> o <label> para lectores de pantalla.
  • Semántica estricta: Reemplaza la "divitis" (uso excesivo de <div>) por etiquetas con significado contextual (<article>, <section>, <header>, <footer>).
  • Jerarquía de encabezados única: Un único <h1> por página, seguido de un orden lógico sin saltarse niveles (<h2> antes de <h3>).

Ejemplos de malas prácticas y etiquetas obsoletas


<!-- Negrita puramente visual -->
<p><b>Este Texto está en negrita pero es una mala práctica</b></p>

<!-- Cursiva puramente visual -->
<p><i>Esto es Texto en cursiva y también es mala práctica</i></p>

<!-- Subrayado visual -->
<p><u>Este texto está subrayado y también es una mala práctica</u></p>

<!-- Etiqueta de tachado obsoleta -->
<p><strike>Este es un texto "strike", tacha el texto pero es una mala práctica. Usa &lt;del&gt; o &lt;s&gt;</strike></p>

<!-- Formato de fuente y color obsoleto -->
<p><font face="Arial" size="4" color="red">Este texto cambia de fuente, tamaño y color con la etiqueta font pero es una mala práctica</font></p>

<!-- Cambio de tamaño obsoleto -->
<p><big>Este texto usa big para aumentar el tamaño de la letra pero es una mala práctica</big></p>

<!-- Alineación centrada obsoleta -->
<p><center>Este texto está centrado con la etiqueta center pero es una mala práctica</center></p>

<!-- Estilos en línea -->
<p style="font-family: sans-serif; font-size: 20px; color: blue;">
  Este texto usa estilos en línea con el atributo style para cambiar la fuente y el tamaño, lo cual es una mala práctica
</p>

6. El DOM (Document Object Model)

El DOM es una interfaz de programación que los navegadores crean al leer tu documento HTML. Es una pieza fundamental en el desarrollo web frontend:

  • Estructura de árbol: El navegador interpreta las etiquetas HTML y las convierte en un árbol jerárquico de nodos (objetos). La etiqueta <html> es la raíz, de la cual nacen ramas como <head> y <body>.
  • El puente con JavaScript: Gracias al DOM, lenguajes como JS pueden leer, modificar, añadir o eliminar elementos, textos y estilos de la página en tiempo real.
  • HTML vs DOM: El HTML es el código estático que tú escribes en tu editor. El DOM es la representación viva que el navegador construye en la memoria y que puedes inspeccionar (pulsando F12 en tu navegador).

7. Accesibilidad Web (a11y) Básica

La accesibilidad web a11y asegura que las personas con algún tipo de discapacidad (visual, auditiva, motora o cognitiva) puedan percibir, entender y navegar por tu web sin barreras.

  • Programamos para personas, no solo para navegadores: Tecnologías asistivas como los lectores de pantalla (Screen Readers) dependen enteramente de cómo esté estructurado tu HTML para poder "leer" la página a usuarios con discapacidad visual.
  • La semántica es accesibilidad: Usar la etiqueta <button> en lugar de un <div> con forma de botón permite que un lector de pantalla anuncie que es un elemento interactivo y que el usuario pueda activarlo usando el teclado (teclas Enter o Espacio).
  • Prácticas obligatorias: Atributos como el alt descriptivo en las imágenes, o el uso de <label> vinculados a sus inputs en los formularios, no son simples recomendaciones académicas; en el mundo empresarial son requisitos legales para cumplir normativas como las WCAG (Web Content Accessibility Guidelines).
